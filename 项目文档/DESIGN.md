# 连接边界设计与限制

## 防御不变量

1. 仅解析严格的 HTTP URL；拒绝用户信息、片段、空白/反斜杠、异常端口与其它协议。实验只做 GET，不发送 cookie、授权头或请求体。
2. 每个重定向跳转和每次重试都重新向**本地**受控 DNS 查询 A 与 AAAA，不把首次解析结果当成后续连接的保证。返回的**全部**地址都要通过当前策略；混合允许/禁用答案整体拒绝。
3. 连接只使用已验证的数字 IP 和端口，不把主机名再交给 socket 解析。连接建立后立刻核对 `getpeername()`，要求实际地址/端口仍符合策略且与选定 DNS 答案相同，然后才发送 HTTP 字节。响应有体积和跳转上限；`total_timeout` 在一次 `fetch()` 开始时建立单一时限，由本项目的 DNS 解析器、数字地址连接器和响应读取器逐步扣减，覆盖 A/AAAA、连接、发送、读取、重定向及重试。`timeout` 另限制单次 socket 操作。连接器若在返回时已耗尽总时限，客户端关闭已连接 socket，不发送 HTTP。
4. 公开地址策略 `PublicOnlyPolicy` 以 Python `ipaddress.is_global` 为公开地址判断，另支持显式禁用网段；回环、私网、链路本地及 IPv4-mapped 回环不通过。`Fetcher` 要求调用方显式提供策略，没有隐式默认策略。`LabOnlyPolicy` 是明确的测试例外，只允许指定名称、回环地址和临时端口；实验不能被当作生产公网策略验收。

## 实验路径

| 场景 | 解析与连接 | 期望 |
| --- | --- | --- |
| 首次允许目标 | `safe.lab.test` → `127.0.0.1`，记录实际 IPv4 对端 | HTTP 200，Host 保留合成名称 |
| 允许的重定向 | 同一受控名称两次解析/直连 | 每跳重查后返回 HTTP 200 |
| 跳向假内部目标 | 重定向至 `internal.lab.test` → `::1` | 连接前拒绝，无内部 HTTP 请求 |
| DNS 变更与重试 | `flip.lab.test` 首次 `127.0.0.1` 得 503，第二次解析变 `::1` | 第二次连接前拒绝，无内部 HTTP 请求 |
| A/AAAA 混合 | 同次解析返回 `127.0.0.1` 与 `::1` | 整体拒绝，无允许目标 HTTP 请求 |
| 错误连接器 | 校验 `127.0.0.1` 后测试适配器误接 `::1` | TCP 连接后实际对端检查拒绝，未发送 HTTP 请求 |
| 公开地址策略 | 合成回环目标遇 `PublicOnlyPolicy` | 连接前拒绝 |
| 慢速响应 | 服务端每 0.18 秒写一个字节，单次读取可在 1 秒内继续收到数据 | 整次抓取约 0.42 秒触发 `DEADLINE_EXCEEDED` |
| 慢速重定向 | 两跳各等待约 0.24 秒 | 共用约 0.38 秒时限，第二跳读取中拒绝 |
| 慢速重试 | 503 与第二次尝试各等待约 0.24 秒 | 共用约 0.38 秒时限，第二次读取中拒绝 |

OWASP 原始防御说明强调先验证目标、检查 DNS A/AAAA，并将连接固定到已验证的 IP；独立预查询不足以防 DNS rebinding，自动重定向应关闭或重新验证。本实验手工处理重定向并记录实际对端：[SSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)、[A10:2021](https://top10.owasp.org/2021/A10_2021-Server-Side_Request_Forgery_%28SSRF%29/)。

## 不能外推的边界

测试适配器的错误路由案例先完成了 TCP 握手才发现对端错误，因此**不能**只依赖应用层 `getpeername()` 阻止所有网络接触；真实部署仍须可信连接器、网络出口限制和必要时隔离。总时限依赖本项目的协作式 DNS 解析器、连接器和读取器；调用方注入不遵守超时的自定义解析器、连接器或策略回调时，Python 不能在本实现内强行中断它们，返回后才会检测超时。它不是任意插件或操作系统调度下的严格墙钟保证。没有实现 HTTPS/TLS/SNI、代理、认证、复杂 DNS、跨进程缓存、所有 URL 编码变体、HTTP/2/3、生产服务发现或真实外部网络行为。`PublicOnlyPolicy` 只做地址分类，本次没有对任何公网目标实际发起连接；不是通用可部署 SSRF 防火墙。包内受控 DNS 服务只支持实验所需的极小 A/AAAA 消息，不能用作通用 DNS 服务。

所有服务、DNS 和客户端在同一机器回环运行；没有扫描真实内网或元数据服务。第三方上游漏洞、实际 CVP 资格及保障措施影响均 **OPEN**。
